## Product Builder Mode

I like building software that has a clear product shape: a useful interface, a sensible data model, a dependable backend, and enough polish that someone can actually enjoy using it.

```text
my default loop
idea -> prototype -> product surface -> backend contract -> feedback -> sharper product
```

## How I Think While Building

<img src="assets/product-map.svg" alt="Product engineering map" width="100%" />

| I ask | Because |
| :--- | :--- |
| What should feel effortless for the user? | The interface should hide the system's complexity. |
| What data shape will survive version two? | Product decisions become database decisions fast. |
| What can fail, retry, or run later? | Reliability is a product feature, not only an infra concern. |
| What should be observable from day one? | Debuggable systems move faster after launch. |
